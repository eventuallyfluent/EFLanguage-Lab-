# Plan 04-03: Pan-Mandarin Review Queue Metadata

## Objective

Make review-only pan-Mandarin island and story queues actionable for human curation while keeping every generated island/story item out of learner-facing exports until accepted by a future review workflow.

## Context

The engine already creates review-only pan-Mandarin islands, stories, premade island packs, premade stories, and a content review queue. The next risk is not lack of generated candidates; it is review material that lacks enough metadata for a human to decide what to accept, revise, or reject.

## Tasks

<task id="04-03-1" title="Audit review queue item shape">
Inspect `src/data/panMandarinContentQueues.ts` and `src/models.ts` to list the current review queue fields and identify the smallest metadata additions needed for curation decisions.
</task>

<task id="04-03-2" title="Add actionable review metadata">
Add or normalize metadata such as source item id, source item type, unlock threshold, known vocabulary coverage or rank bounds, blocking reasons, and suggested curation action when those fields are missing from review queue items.
</task>

<task id="04-03-3" title="Lock review-only behavior in tests">
Add tests that every pan-Mandarin review queue item is review-only, has concrete curation metadata, and does not appear in active learner-facing sentences or curriculum packs. Run `npm.cmd test` and update `.planning/BASELINE.md` if outputs change.
</task>

## Success Criteria

- Review queue items contain enough metadata for human curation decisions.
- Review-only island/story material remains excluded from active learner-facing outputs.
- `npm.cmd test` passes.
