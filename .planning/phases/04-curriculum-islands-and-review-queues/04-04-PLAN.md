# Plan 04-04: Curriculum Output Contract And Web Data Alignment

## Objective

Align generated engine output and web-consumable data around a clear contract: active learner-facing content, locked future content, draft material, and review-only material must remain distinguishable.

## Context

`src/generator.ts` writes both `output/` artifacts and `public/data/` copies. As Phase 4 strengthens curriculum and review queues, the generated contract should make it difficult for the web app or future tooling to treat draft/review-only material as active lessons.

## Tasks

<task id="04-04-1" title="Define curriculum content contract">
Add or update a generated contract/report that names active learner-facing outputs, locked outputs, draft outputs, and review-only outputs, with enough counts/status fields for consumers to validate their usage.
</task>

<task id="04-04-2" title="Align public data copies">
Ensure `public/data/` receives the relevant contract or report and that the web app reads generated data without duplicating engine policy logic. Keep UI changes minimal unless required by the data contract.
</task>

<task id="04-04-3" title="Verify engine and web build">
Run `npm.cmd test` and `npm.cmd run web:build`. Update `.planning/BASELINE.md` and Phase 4 notes with the final counts, test totals, and any sandbox-specific build caveat.
</task>

## Success Criteria

- Generated output clearly distinguishes learner-facing, locked, draft, and review-only surfaces.
- Web-consumable data preserves that distinction.
- `npm.cmd test` passes.
- `npm.cmd run web:build` passes, with any sandbox rerun documented if needed.
