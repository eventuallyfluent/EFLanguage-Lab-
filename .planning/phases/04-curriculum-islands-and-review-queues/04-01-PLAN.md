# Plan 04-01: Learner-Facing Curriculum Boundary Hardening

## Objective

Make the curated-only learner-facing curriculum boundary explicit and regression-tested so raw generated, draft, locked, or review-only content cannot drift into active learner outputs.

## Context

Phase 3 separated raw CI exposure deficits from authorable learner-facing work. Phase 4 applies the same discipline to curriculum surfaces. Existing tests already check that learner-facing sentences are curated-only and pack-backed; this plan should inspect those tests first, then add only the missing guardrails.

## Tasks

<task id="04-01-1" title="Audit active learner-facing export boundaries">
Review `src/generator.ts`, `src/curriculum.ts`, and current curriculum tests to identify which generated arrays are active learner-facing, locked future content, draft review material, and review-only material. Keep the implementation changes narrowly scoped to any missing boundary checks.
</task>

<task id="04-01-2" title="Add curated-only regression coverage">
Add tests that fail if active `sentences`, active `curriculumPacks`, or pack-derived learner-facing sentences contain anything other than curated reviewed content. Add complementary checks that `draftSentences` remain draft-only and are not included in active learner-facing packs.
</task>

<task id="04-01-3" title="Refresh baseline and verification notes">
Run `npm.cmd test`, update `.planning/BASELINE.md` if generated counts or test counts change, and record any boundary names or output distinctions that future plans must preserve.
</task>

## Success Criteria

- Active learner-facing sentence exports are curated-only.
- Draft/template-generated material remains separate from active curriculum.
- Locked future packs are not treated as current learner-facing content.
- `npm.cmd test` passes.
