# Plan 03-03: Coverage Deficit Reporting Without Forced Authoring

## Objective

Make remaining exposure deficits visible by authorability class so the project can see what still needs work without converting early non-ready targets into learner-facing authored content.

## Context

The coverage report should be honest about deficits while preserving the validator boundary. Some deficits are real but not ready for normal authored CI because the known vocabulary pool is too thin. Reporting should distinguish "needs exposure eventually" from "safe to author now."

## Tasks

<task id="03-03-1" title="Audit current deficit outputs">
Inspect generated `ci-coverage-report.json`, `ci-curation-queue.json`, `ci-authorable-curation-queue.json`, `ci-authoring-packets.compact.json`, `authored-ci-validation-report.json`, and `promoted-authored-ci-stream.json` after generation. Record current counts in `.planning/BASELINE.md`.
</task>

<task id="03-03-2" title="Add authorability-aware reporting">
If the coverage report or pipeline contract does not already expose the distinction clearly enough, add a small authorability summary so raw deficits, ready authorable work, and non-ready deficits can be inspected without reading multiple files manually.
</task>

<task id="03-03-3" title="Test reporting semantics">
Add tests proving deficit reporting does not imply all deficits are ready to author. The tests should protect the presence of non-ready categories and the continued separation of authorable work.
</task>

<task id="03-03-4" title="Regenerate and verify output">
Run generation through the test suite, inspect output diffs, and confirm no learner-facing stream gains unvalidated or fragment-like authored lines.
</task>

## Success Criteria

- Coverage/reporting exposes remaining deficits and authorability state.
- Non-ready deficits are visible but excluded from normal authoring packets.
- Authored stream remains promotion-gated.
- Baseline notes identify current Phase 3 output counts.
- `npm.cmd test` passes.
- `npm.cmd run web:build` passes if generated public data or app-facing output shape changes.
