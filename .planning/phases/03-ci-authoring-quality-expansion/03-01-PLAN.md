# Plan 03-01: Authorability Contract And Packet Provenance

## Objective

Make the raw deficit queue, authorable queue, and authoring packet provenance impossible to confuse. Authoring packets must continue to derive from `ready` queue items only.

## Context

Phase 3 is about increasing usable CI authoring throughput without letting raw exposure deficits become learner-facing fragments. The engine already labels queue items as `bootstrap-only`, `needs-more-known-vocabulary`, or `ready`. This plan turns that behavior into a stronger tested contract and clarifies pipeline metadata where useful.

## Tasks

<task id="03-01-1" title="Lock raw queue versus authorable queue behavior">
Add or strengthen tests proving the raw CI curation queue may contain non-ready items while `buildAuthorableCiCurationQueue()` excludes them. The tests should assert authorability states by contract, not just by incidental array indexes.
</task>

<task id="03-01-2" title="Lock packet source provenance">
Add or strengthen tests proving curation batches, authoring packets, and compact packets are built from the authorable queue and do not include `bootstrap-only` or `needs-more-known-vocabulary` targets.
</task>

<task id="03-01-3" title="Clarify pipeline contract output">
If the existing `ci-pipeline-contract.json` text is ambiguous, update the contract builder so generated output states that authoring packets derive from the authorable queue. Keep this as metadata or explanatory contract text; do not alter queue semantics.
</task>

<task id="03-01-4" title="Update baseline notes">
Update `.planning/BASELINE.md` with the current authorability contract and any relevant current counts observed during verification. Avoid hand-editing generated output.
</task>

## Success Criteria

- Raw deficit queue remains separate from the authorable queue.
- Authoring batches and packets contain only `ready` items.
- Bootstrap-only and needs-more-known-vocabulary targets remain excluded from normal CI authoring packets.
- Generated pipeline contract explains the distinction clearly.
- `npm.cmd test` passes.
