# Plan 02-02: Parser And Ranking Regression Hardening

## Objective

Make pan-Mandarin parser and ranking behavior harder to accidentally break. This should focus on deterministic tests and small diagnostics, not new source acquisition.

## Context

`buildPanMandarinVocab()` combines TUBELEX, SUBTLEX-CH, HSK, and TOCFL into a 10k concept list. Tests currently check broad counts and some top entries. Phase 2 needs stronger protection for ordering, source membership, variant retention, and warning behavior before the ranking formula grows more complex.

## Tasks

<task id="1" name="Add parser fixture invariants">
Strengthen tests for `loadPanMandarinRawSources()` so they assert stable top entries, non-empty source-specific fields, and expected source counts without depending on every row.
</task>

<task id="2" name="Add ranking determinism invariants">
Add tests around `buildPanMandarinVocab()` that verify global ranks are sequential, communication path ranks are integer/unique enough for ordering, source memberships are stable for representative entries, and repeated builds produce the same first-page concept IDs.
</task>

<task id="3" name="Expose focused diagnostics if needed">
If tests need clearer failure messages, add small helper functions or test-local diagnostics. Avoid broad refactors and do not change the ranking formula unless a test exposes an actual bug.
</task>

## Must Haves

- No network dependency.
- No new external source files.
- No silent source-weight redistribution.
- No weakened existing tests.
- Ranking behavior stays deterministic across repeated runs.
