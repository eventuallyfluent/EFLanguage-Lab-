# Plan 02-01: Source Audit Contract Cleanup

## Objective

Make source-role and import-mode reporting unambiguous across the legacy source audit, pan-Mandarin source audit, tests, and project metadata. This plan should correct misleading HSK-backbone wording without changing learner-facing generation behavior.

## Context

Phase 2 requires source audits to clearly show file-backed, fixture-backed, missing, and manual source families. Current output already does this in broad strokes, but there is drift: `package.json` still describes an HSK-only MVP, and legacy source audit notes still call HSK the permission backbone even though `PROJECT_TRUTH.md` says the 10k path is concept-backed and HSK/TOCFL are reference sources.

## Tasks

<task id="1" name="Tighten source audit language">
Update source audit notes so they distinguish ranking sources, learner/reference sources, fixture metadata, missing sources, and manual cleanup. Do not change import modes to make warnings disappear.
</task>

<task id="2" name="Align project metadata and docs">
Update `package.json` description and any directly related docs touched by this plan so they match the pan-Mandarin 10k CI engine direction. Keep `PROJECT_TRUTH.md` as the binding wording.
</task>

<task id="3" name="Lock the audit contract with tests">
Add or strengthen tests that assert source audit roles/import modes for both legacy and pan-Mandarin audits, including warnings for fixture-backed and missing weighted sources.
</task>

## Must Haves

- `MOVIE_FREQUENCY` and `BOOK_FREQUENCY` remain fixture-backed until real files are imported.
- `SPOKEN_CORPUS` and `BALANCED_WRITTEN` remain missing and warning-producing.
- `HSK_3_0_REFERENCE` and `TBCL_TOCFL_REFERENCE` are clearly learner/reference coverage sources, not the pan-Mandarin ranking foundation.
- No learner-facing sentence, CI packet, or web UI behavior changes are introduced in this plan.
