# Plan 02-03: Variant And Source Role Documentation

## Objective

Make regional/script variant expectations and source-role boundaries explicit enough that future expansion does not collapse Mainland/Taiwan forms or misrepresent incomplete source coverage.

## Context

`PROJECT_TRUTH.md` requires Mainland and Taiwan variants to share concept IDs where appropriate while preserving separate regional forms, script forms, pronunciation, frequency, and examples. The current implementation has a basic variant model and tests for at least one traditional-vs-simplified variant, but the future work boundary needs to be clearer before Phase 3 authoring work depends on this path.

## Tasks

<task id="1" name="Document variant invariants">
Update `.planning/PAN_MANDARIN_VOCAB_PLAN.md` or a focused planning note so future work knows which fields must stay distinct: concept ID, simplified form, traditional form, region, pronunciation region, source refs, and example status.
</task>

<task id="2" name="Add representative variant/source tests">
Strengthen tests so representative concepts prove regional/script metadata survives export. Prefer durable assertions over brittle full-list snapshots.
</task>

<task id="3" name="Refresh baseline and next risks">
Update `.planning/BASELINE.md` or `.planning/ISSUES.md` with any newly clarified source/variant risks, including what still needs a real spoken corpus or balanced written corpus.
</task>

## Must Haves

- Do not add fake regional mappings to satisfy tests.
- Do not create a broad traditional-conversion project in this phase.
- Do not make HSK or TOCFL control ranking foundation.
- Keep missing sources visible in audit warnings.
